# DSH 插件目录全自动运营方案

## 目标

将当前“自动发现、人工审核、手动合并”升级为：自动发现、自动判断、自动生成双语内容、自动更新目录和文档、自动校验、自动发布、自动生成并送达收录报告。

高置信度插件全程无人值守；只有异常项目进入每周汇总。本仓库继续作为完全独立的新仓库，不继承、不引用、不关联任何其他目录仓库及其 Git 历史。

## 用户流程

插件开发者只需公开插件仓库、完善 README 和许可证，并添加 `dsh-plugin` Topic。系统每天自动发现；符合标准的项目直接进入中英文目录。Issue 提交表单继续作为主动申请和信息纠错通道。

仓库维护者日常只接收两类通知：成功收录报告，以及需要人工判断的每周异常汇总。

## 每日自动流程

1. 获取 GitHub `dsh-plugin` Topic 下的全部仓库。
2. 根据 repository ID 识别新增、重命名、转移和重复项目。
3. 读取仓库元数据、文件结构和 README，但不安装或执行候选代码。
4. 通过确定性规则排除 Fork、模板、教程、目录、空仓库等项目。
5. 使用 GitHub Models 输出是否为插件、四大分类、双语描述、证据及置信度。
6. 高置信度项目自动进入正式目录，其他项目进入异常池。
7. 更新结构化数据、中英文 README、CHANGELOG 和本次收录报告。
8. 在同一任务中完成结构、重复项、双语一致性和幂等校验。
9. 校验通过后提交 `main`，再回读远端提交确认发布成功。
10. 使用最终提交 SHA 创建唯一的 GitHub Issue 收录报告。

## 自动准入规则

自动收录必须同时满足：公开可访问、非 Fork、非模板、非归档、存在 README、存在实际代码或插件结构、明确与 DSH 插件相关、有用途和使用信息、无重复、分类明确、双语描述合规，且模型输出为高置信度。

插件身份不明确、许可证缺失、内容不足、分类歧义、疑似重复、模型结果不稳定或描述无法事实化时，不自动收录。自动排除项不逐条通知。

模型只能返回结构化 JSON；分类限定为四个既有大类，描述限定为单句事实表述，禁止排名、营销语言以及虚构的兼容性、性能或安全结论。模型输出未通过 Schema 校验时进入异常池。

## 成功收录事务

一次成功收录必须同步完成：

- 更新 `data/plugins.json` 及 repository ID；
- 重新生成 `README.md` 和 `README.zh.md`；
- 更新总数、分类统计和最近复核日期；
- 更新 `CHANGELOG.md` 的 `Unreleased`；
- 生成 `reports/sync/YYYY-MM-DD-<run-id>.md`；
- 通过全部自动化校验；
- 提交并推送 `main`；
- 回读远端提交；
- 创建并指派成功报告 Issue。

没有新增时不产生提交和通知。最终提交 SHA 是报告的唯一标识；Issue 送达失败时，后续任务根据仓库报告自动补发，不重复收录。

## 报告内容

报告包含执行时间、运行编号、最终提交、收录前后总数、新增插件清单、分类、双语描述、准入依据、规则与模型结果、文档更新结果、校验结果、异常候选摘要，以及“未执行插件代码、不代表安全认证”的边界声明。

## 异常与下架

低置信度项目每周汇总为一个 Issue。一次不可访问只记录，连续三次标记异常，连续 30 天进入待下架列表。归档、Topic 移除和删除均不直接自动移除正式条目；仓库重命名或转移则根据 repository ID 自动修正链接。

## 落地阶段

1. 观察模式：接入模型并输出模拟准入结果，不发布，持续至少 7 次有效扫描。
2. 自动发布：启用高置信度准入、文档生成、报告和 `main` 提交。
3. 运营完善：启用异常周报、失效检测、报告补发和阈值调优。

## 验收标准

- 高置信度插件无需人工操作即可进入目录；
- 中英文 README、结构化数据和 CHANGELOG 同步更新；
- 每次成功收录都有永久报告和 GitHub Issue 通知；
- 重复运行不重复收录、不重复报告；
- 无新增时不提交、不通知；
- 任一发布校验失败时不更新 `main`；
- 低置信度项目不会误发布；
- 候选代码从未被安装或执行；
- 本仓库不与任何其他目录仓库建立 Git 或自动同步关系。
